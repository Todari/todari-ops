# 자동 데일리 기록

사람이 봇에 적지 않아도 볼트의 데일리 노트가 이어지도록, 봇이 이미 가진 근거로 하루를 대신 적는다.
구현은 `src/daily-log/`(수집·예약), `src/vault/editor.ts`의 `upsertAutoLog`(노트 편집),
`src/vault/mutations.ts`의 `writeVaultDailyLog`(커밋·push)다.

## 언제

- 매일 `DAILY_LOG_TIME`(KST, 기본 `00:40`)에 한 번, 그 시각 기준 **어제**(KST 00:00–24:00)를 쓴다.
  자정 뒤 시각으로 두어야 한다. 자정 전으로 옮기면 그제의 기록을 쓰게 된다.
- 그 시각에 봇이 내려가 있었으면 다음 시작 때 따라잡는다(예약 이름 `daily-log`, 다이제스트와 같은 방식).
- 놓친 날은 다음 실행이 채운다. 실행마다 마지막으로 살펴본 날 다음부터 어제까지를 오래된 날부터 쓴다(최근 7일까지).
  근거가 없어 쓰지 않은 날도 살펴본 날로 쳐서 다시 보지 않는다.
- 쓰다가 실패한 날(볼트 push 충돌, 60초 안에 끝나지 않은 git 명령 등)은 Sentry 로 가고 뒤의 날을 막지 않는다.
  그날만 다음 실행(다음 날 밤)에서 다시 쓰고, 7일이 지나도록 쓰지 못하면 포기한다.
- 뒤늦게 쓰는 날에는 그때만 있던 근거가 빠진다: 인스타 실적과 내일 첫 작업은 가장 최근 것 하나만 남아 있다.
- 밤에는 디스코드에 아무것도 올리지 않는다. 아침 다이제스트에 `📓 어제 기록` 한 줄(예: `커밋 12 · 배포 3 · 새 노트 2`)만 붙는다.
  어제의 기록을 썼을 때만 붙고, 뒤늦게 채운 지난 날의 요약은 싣지 않는다.

## 무엇을 모으나

출처 하나가 실패하면 경고만 남기고 나머지로 쓴다. 전부 비면 노트를 만들지 않는다.

| 구획 | 근거 |
|---|---|
| 코드 | GitHub 커밋 검색 한 번(`author:<로그인> committer-date:<그날>`, 최대 100건). 레포별 건수와 첫 줄 5개. 볼트 레포와 `vault:`·`vault backup:` 커밋은 뺀다 |
| 운영 | 봇이 관측한 이벤트(`events.json`): 배포·배포 실패·CI 실패·PR 열림/머지·장애/복구·Sentry·자동진단 |
| 인스타 게시 | 워치독이 보낸 실적 문구. 그날의 다음 날에 받은 것만 쓴다(문구가 "어제"를 말하기 때문) |
| 볼트 | 그날 커밋으로 새로 생긴 노트. `의사결정`·`TIL`·`트러블슈팅` 폴더 또는 최상위 폴더로 묶어 위키링크로. `데일리/`·`Archive/`·`템플릿/`은 뺀다 |
| 일본어 | 그날 푸시된 "오늘의 표현" |
| 오늘의 3개 | 그날 아침 다이제스트에서 고른 할 일과 완료 여부([task-loop.md](task-loop.md)). 체크박스가 아닌 글머리(`- ✅`·`- ⬜`)로 쓴다 |
| 내일 첫 작업 | 그날 저녁 체크인에서 정한 것. 기록 시각 뒤에 정하면 이 구획에는 빠지고 다이제스트에만 나온다 |

커밋은 **작성자**로 찾는다. 로그인은 `DAILY_LOG_AUTHOR`, 비어 있으면 `GITHUB_TOKEN`의 주인이다(`GET /user`, 알아낸 뒤에는
봇이 떠 있는 동안 다시 묻지 않는다). 소유자로 묶지 않으므로 개인 레포든 조직 레포든 그 사람이 쓴 커밋만 잡히고,
조직 레포에 올라온 다른 사람·봇의 커밋은 빠진다. `DAILY_LOG_OWNERS`(쉼표 구분)를 두면 그 사용자·조직의 레포로 더 좁힌다.
로그인을 알아내지 못한 때(토큰 없음·`/user` 실패)에만 예전처럼 소유자의 레포 전체를 본다: `DAILY_LOG_OWNERS`,
비어 있으면 `src/projects.ts` 카탈로그 레포의 소유자들. 이때는 조직 레포의 다른 사람 커밋도 함께 잡힌다.

커밋 검색의 범위가 곧 한계다: 기본 브랜치에 올라온 커밋만 잡히고(브랜치 작업은 머지·스쿼시된 날에 보인다),
커밋의 작성자 이메일이 그 GitHub 계정에 연결돼 있어야 한다.

## 노트 형식

`데일리/YYYY-MM-DD.md`. 근거가 있는 구획만 나온다. frontmatter 는 쓰지 않고, 첫 제목 위에는 아무것도 두지 않는다.

```
## 자동 기록

### 코드
- **todari-ops** 3건: feat: …; fix: …; docs: …
### 운영
- 배포 2건 (todari, lvti)
### 인스타 게시
게시: 1/3건
### 볼트
- 의사결정: [[2026-10-11 가격 정책]]
### 일본어
- お疲れ様です (おつかれさまです) — 수고하셨습니다
### 내일 첫 작업
- todari-ops · 배포 확인

## 메모
```

노트가 이미 있으면 `## 자동 기록`부터 다음 `# `·`## ` 제목 앞까지만 갈아 끼우고 나머지는 바이트 그대로 둔다.
구획이 없으면 노트 맨 위에 넣는다(사람이 둔 frontmatter 가 있으면 깨지지 않게 그 바로 뒤).
직접 쓰는 글은 `## 메모` 같은 다른 제목 아래에 둔다 — `## 자동 기록` 안에 쓴 글은 다음에 봇이 그 날짜를 다시 쓸 때 지워진다.

### 맥과 같은 날 노트를 고칠 때

볼트는 `.gitattributes`로 `데일리/*.md`를 git union 드라이버에 맡긴다. 맥과 봇이 같은 날의 노트를 각자 만들거나 고쳐도
병합이 멈추지 않고 양쪽 줄이 모두 남는다(이어 붙는 순서는 git 이 정한다). 그래서 이 노트에는 파일 맨 위에 있어야만
뜻이 통하는 것을 쓰지 않고, 봇이 쓰는 것은 `## ` 제목으로 시작하는 구획뿐이다. 봇은 자기 구획이 파일 어디에 있든 찾아서 갈아 끼운다.
맥이 먼저 올려 봇의 push 가 거절되면 봇이 rebase 로 같은 병합을 거쳐 다시 올린다.

## 저녁 체크인과의 관계

21:30 체크인 메시지에 같은 수집기로 만든 `오늘 한 일 (지금까지)`(코드·운영·볼트)와 "내일 첫 작업" 후보 버튼(최대 3개)이 붙는다.
후보는 마감이 가까운 할 일, 오늘 커밋한 프로젝트의 첫 할 일, 나머지 노트의 첫 할 일 순이다.
버튼을 누르면 모달 없이 저장되어 다음 날 다이제스트 맨 위와 그날의 자동 기록에 들어간다. 어느 노트의 어느 할 일인지도
함께 남아, 다음 날 고르기 메뉴가 그 할 일을 맨 앞에 미리 골라 둔다([task-loop.md](task-loop.md)).
후보는 올린 뒤 12시간 동안 누를 수 있고, 그사이 봇이 재시작해도(저녁 배포) 동작한다. 그 저녁의 후보는
`/data/checkin-candidates.json`에 날짜별로 두고 7일 뒤 지운다. 만료되면 `📝 회고 쓰기`로 적는다.

## 설정

| 환경변수 | 기본값 | 뜻 |
|---|---|---|
| `DAILY_LOG_TIME` | `00:40` | KST `HH:MM`. **비우면 자동 기록을 끈다** |
| `DAILY_LOG_AUTHOR` | (비어 있음) | 커밋의 작성자로 볼 GitHub 로그인. 비우면 `GITHUB_TOKEN`의 주인 |
| `DAILY_LOG_OWNERS` | (비어 있음) | 커밋 검색을 이 GitHub 사용자·조직의 레포로 더 좁힌다. 쉼표로 구분 |

볼트 레포(`VAULT_REPO_URL`)에 push 할 수 있는 `GITHUB_TOKEN`이 필요하다. `/data/daily-log.json`에는 마지막으로 쓴 기록의
날짜와 요약(`date`·`summary`), 어디까지 살펴봤는지(`processed`), 살펴봤지만 아직 쓰지 못한 날들(`pending`)이 남는다.
파일을 지우면 다음 실행은 어제만 쓴다.
