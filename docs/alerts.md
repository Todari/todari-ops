# 인스타 채널 알림 정책

워치독(`scripts/instagram-watchdog.py`, EC2 크론 15분)이 서명된 페이로드를 봇의 `/webhook/instagram`으로 보내고,
봇(`src/webhook/instagram-handler.ts`)이 채널에 표시한다. 페이로드의 `alert_level`이 표시 방식과 채널을 정한다.

## 채널

채널은 출처가 아니라 "사람이 움직여야 하는가"로 나눈다.

| 묶음 | 채널 | 환경변수 | 들어오는 것 |
|---|---|---|---|
| 지금 | #상태판 | `STATUS_CHANNEL_ID` | 봇이 고쳐 쓰는 메시지 하나: 계정별 게시 실적·열린 문제, 서비스 상태 |
| 지금 | #조치-필요 | `ALERTS_CHANNEL_ID` | 운영자 확인 필요, 게시 중단·재개, 서비스 다운, Sentry, CI 실패, PR 리뷰 |
| 지금 | #daily | `DIGEST_CHANNEL_ID` | 일간 요약(어제 인스타 게시 실적 포함), 주간 요약, 주간 인스타 리포트 |
| 로그 | #로그-게시 | `INSTAGRAM_CHANNEL_ID` | 게시 성공, 지연 감지, 지연 게시 완료, 게시기가 직접 보내는 실패 기록 |
| 로그 | #로그-배포 | `DEPLOY_LOG_CHANNEL_ID` | PR 머지 |

서버 알림 기본값을 "@멘션만"으로 두면 푸시는 소유자 멘션이 붙는 알림에만 온다.
멘션은 `ownerMention()`(`src/discord/alerts.ts`)으로 붙인다. 새 알림을 만들 때 사람이 움직여야 하면 붙이고, 복구·성공이면 붙이지 않는다.

| 알림 | 멘션 | 비고 |
|---|---|---|
| 인스타 `action`·`outage` | 예 | 아래 알림 수준 참고 |
| 서비스 다운 | 예 | 복구되면 그 메시지를 초록으로 고쳐 쓴다(푸시 없음) |
| 메모리·디스크·스왑 경고, 서버 재부팅 감지 | 예 | 회복 알림은 멘션 없음 |
| 도메인·인증서·토큰 만료 임박 | 예 | |
| Sentry 이슈, CI 실패, Vercel 배포 실패 | 예 | Vercel 복구는 멘션 없음 |
| PR 열림·리뷰 준비 | 다른 사람이 연 PR만 | 저장소 소유자 본인과 봇이 연 PR은 멘션 없음 |
| 에이전트 권한 요청, 1분 넘은 작업 완료, 리마인더 | 예 | 해당 스레드·채널에서 |

평상시 Vercel 프로덕션 배포 성공은 #로그-배포로 간다.

## 알림 수준

| alert_level | 언제 | 표시 | 무음 | 소유자 멘션 |
|---|---|---|---|---|
| `delay` | 지연 감지, 자동 복구 시작 | 노랑 "게시 지연 · 자동 복구 중" | 예 | 아니오 |
| `recovered` | 지연 뒤 게시 완료 | 초록 "지연 게시 완료" | 예 | 아니오 |
| `action` | 자동 복구 실패, 24시간 경과, 게시 취소, 공구함 발행 결과 확인 필요 | 빨강 "운영자 확인 필요" | 아니오 | 예 |
| `outage` | 한 계정의 한 유형이 연속 미게시 | 빨강 "게시 중단" | 아니오 | 예 |
| `outage_resolved` | 그 유형의 게시 재개 | 초록 "게시 재개" | 아니오 | 아니오 |
| `outage_closed` | 새 예정이 없어 중단 경보를 닫음 | 회색 "게시 중단 종료 · 새 예정 없음" | 예 | 아니오 |

`action`·`outage`·`outage_resolved`·`outage_closed`는 #조치-필요로, `delay`·`recovered`는 #로그-게시로 간다.

## 문제 하나에 메시지 하나

- 워치독은 한 문제의 시작과 끝에 같은 `source_key`를 쓴다. 봇은 문제마다 처음 올린 메시지의 위치를
  `/data/instagram-problems.json`에 기억한다.
- 닫는 알림(`recovered`, `outage_resolved`, `outage_closed`)은 새 메시지를 보내지 않고 그 메시지를 고친다.
  제목과 색이 바뀌고 "닫힘" 칸이 붙으며 멘션은 지워진다. 수정은 푸시를 만들지 않는다.
- 그래서 #조치-필요에 남은 빨간 메시지가 아직 열려 있는 문제다. 원 메시지를 못 찾으면 새 메시지로 보낸다.
- 확인 필요로 넘긴 건이 뒤늦게 게시되면(수동 조치·늦은 복구) 워치독이 `recovered`를 보내 그 알림을 닫는다.
- 같은 문제를 같은 채널에 다시 알릴 때는 새 메시지를 올리고 먼저 올린 것을 지운다.

## 다시 알림과 확인함

- 게시 중단이 열린 채 사흘이 지나면 워치독이 같은 키로 다시 알린다(`OUTAGE_REMIND_EVERY`). 멘션이 다시 간다.
- 멘션이 붙는 알림(`action`, `outage`)에는 "확인함" 버튼이 있다. 누르면 메시지가 회색으로 바뀌고 멘션이 지워지며,
  그 문제는 닫힐 때까지 다시 알리지 않는다. 닫는 알림은 그대로 적용된다.

- `alert_level`이 없는 실패 이벤트(각 계정 게시기가 직접 보내는 것)는 예전 표시 그대로다.
- 봇의 중복 억제 키에 `alert_level`이 들어간다. 같은 작업이라도 단계가 다르면 각각 표시된다.
- 원칙: 푸시와 멘션은 사람이 움직여야 하는 알림에만 건다. 지연 감지와 복구 완료는 기록으로만 남긴다.

## 상태판

- 워치독이 생존 신호에 계정별 현황(오늘·어제 게시/예정, 게시 중단, 확인 필요, 지연)을 실어 보낸다.
  봇은 여기에 서비스 상태와 볼트 동기화 시각을 붙여 #상태판의 메시지 하나를 고쳐 쓴다(15분마다, 푸시 없음).
- 하루는 KST 날짜로 묶는다. 메시지 위치는 `/data/status-board.json`에 있고, 지워지면 새로 올린다.
- "워치독 확인" 시각이 30분 넘게 지나 있으면 워치독이 멈춘 것이다(아래 생존 감시가 따로 알린다).

## 연속 미게시 경보

- 조건: (계정, 유형)별로 기한이 지난 최근 작업이 연속 3건 이상 미게시(`OUTAGE_STREAK`). 취소된 작업은 세지 않는다.
- 유형별로 센다. 계정 단위로 세면 주간·용어편 같은 다른 유형의 게시가 연속을 끊어 매일 나가야 할 유형이 멈춘 것을 가린다.
- 경보에는 그 미게시 작업들의 주된 실패 사유 두 가지가 붙는다(원장의 마지막 복구 오류를 묶어 센다).
  "복구 시도 기록 없음"이면 자동 복구가 그 작업들을 시도하지 못한 것이다.
- 한 번 열리면 그 유형이 다시 게시될 때까지 열려 있고, 재개되면 `outage_resolved`를 한 번 보낸다.
- 새 예정이 3일 넘게 없으면(시즌 종료·휴식기) 푸시 없이 닫고 `outage_closed`로 원 메시지만 고친다(`OUTAGE_STALE_AFTER`).
- 열린 경보는 아침 다이제스트의 "인스타 게시" 칸에 "게시 중단 중" 줄로 함께 나간다.

## 아침 브리프

- 워치독은 어제 게시 실적(유형별 게시/예정, 최근 7일, 게시 중단 중)을 따로 보내지 않고 생존 신호에 싣는다.
  봇이 마지막으로 받은 것을 보관했다가 아침 다이제스트(`DIGEST_TIME`)의 "인스타 게시" 칸에 넣는다.
- 워치독 현황이 2시간 넘게 오지 않았으면 그 사실을 칸 맨 앞에 적는다.

## 설치

워치독은 main 푸시로 배포되지 않는다. 커밋한 뒤 `deploy/install-instagram-watchdog.sh`로 EC2에 따로 설치한다.
작업 트리의 파일을 그대로 복사하므로 커밋본에서 실행한다.

## 생존 감시

- 워치독은 실행마다 봇에 생존 신호(`status: "heartbeat"`)를 보낸다. 봇의 `/healthz`는 이 신호가 30분 넘게 끊기면 `instagram-watchdog=stale`로 응답한다.
- `.github/workflows/monitor.yml`이 30분마다 `/healthz`를 본다. 실패하면 배포 알림 웹훅으로 `@everyone` 멘션과 함께 알린다. 봇이 죽어도 이 경로는 살아 있다.

## 에이전트 세션과 예약 게시

- 권한 요청에는 소유자 멘션이 붙고 `PERMISSION_TIMEOUT_MS`(기본 10분) 동안 기다린 뒤 자동 거부한다.
- 1분 넘게 걸린 턴이 끝나면 그 스레드에 소유자를 멘션한다. 직접 취소한 턴은 멘션하지 않는다.
- 일간·주간 요약, 저녁 체크인, 일본어 푸시는 마지막 게시일을 `/data/scheduled-posts.json`에 남긴다.
  예약 시각에 봇이 내려가 있었으면 다음 시작 때 그날 한 번 따라잡는다. 수동 명령은 기록하지 않는다.
