# 위임 버튼 (시험)

아침 다이제스트의 `▶` 버튼은 디스코드 스레드에서 대화형 Claude Code 세션을 띄운다. 도구 승인을 눌러 줘야 해서
자리를 비우면 멈추고, 그래서 쓰이지 않았다. `🤖 위임`은 지켜보지 않아도 되는 길을 레포 하나에서 시험한다.
버튼을 누르면 그 할 일이 `@claude` 를 부르는 GitHub 이슈로 올라가고, 그 레포에 설치된 Claude Code GitHub Action 이
브랜치에서 작업한다. 열린 PR 은 다음 날 아침 다이제스트의 레포별 "열린 PR"에 보인다.
구현은 `src/delegate/index.ts`(준비 확인·버튼·이슈), `src/digest/daily.ts`(버튼 줄), `src/github/api.ts`의 `ghPost`다.

## 버튼이 하는 일

- **나오는 곳**: 아침 다이제스트와 수동 `/digest`. `▶` 버튼과 같은 후보(최대 3개) 가운데 레포가 준비된 것마다
  `🤖 위임 <slug>: <할 일>` 버튼이 한 줄에 붙는다. 준비된 레포가 없으면 줄도 없다.
- **준비된 레포**: 기본 브랜치에 `.github/workflows/claude.yml` 이 있는 레포다. 다이제스트를 올릴 때 GitHub 에 묻는다.
  3초 안에 답이 없거나 조회가 실패한 레포는 버튼 없이 게시하고, 있다는 답은 봇이 떠 있는 동안 한 시간 기억한다.
- **누르면**: 비공개 레포는 바로 이슈를 올린다. 제목은 할 일(120자까지), 본문은 `@claude` 를 부르는 한 줄, 할 일 전문,
  볼트 노트 이름, 그리고 진행 방법 네 가지다: 새 브랜치에서 작업하고 PR 을 연다 · 기본 브랜치에 직접 push 하지 않는다 ·
  레포의 테스트를 돌려 결과를 PR 설명에 적는다 · 할 일이 불분명하면 멈추고 이슈에 묻는다.
- **올라가면**: 다이제스트 메시지에서 그 버튼만 사라지고 임베드의 `🤖 위임` 칸에 `🤖 위임함: <이슈 주소>` 가 적힌다.
- **실패하면**(공개 여부 확인 실패, 이슈 생성 실패): 이유를 본인에게만 보이는 메시지로 알리고 다이제스트는 그대로 둔다.
  다시 누르면 다시 시도한다.
- **한 번만**: 버튼 id 는 레포·노트·문장으로 정해진다. 연달아 누르거나 다음 날 다이제스트의 같은 버튼을 눌러도
  이슈를 또 올리지 않고 이미 올린 이슈의 주소를 답한다. 다시 시키려면 그 이슈에 `@claude` 댓글을 단다.
- **같은 제목의 열린 이슈**: 올리기 직전에 열린 이슈(최근 50개, PR 제외)를 읽어 제목이 같으면 새로 올리지 않고 그 이슈를 올린 것으로 적는다. 이 조회가 실패하면 올리지 않고 사유를 알린다.
- **상태**: `/data/delegations.json`(버튼 id → 레포·노트·할 일·올린 이슈)에 남아 버튼이 봇 재시작을 넘긴다.
  다이제스트에 마지막으로 실린 지 7일이 지난 버튼은 만료된다. 파일을 지우면 걸려 있던 버튼이 만료되고
  "이미 올렸다"는 기록도 사라진다.

## 공개 레포

공개 레포(`GET /repos/<레포>` 의 `private` 이 `false`)에 올리면 할 일 문장과 볼트 노트 이름이 누구나 볼 수 있는 이슈가 된다.
그래서 첫 탭에서는 올리지 않는다. 무엇이 공개되는지 본인에게만 보이는 메시지로 보여 주고, 거기 달린
`공개 이슈로 올리기` 버튼을 눌러야 올린다. 공개 여부를 확인하지 못했을 때도 올리지 않는다
(비공개라는 답을 받았을 때만 묻지 않고 올린다).

## 레포마다 한 번 해 둘 일

1. 그 레포에서 Claude Code 를 열고 `/install-github-app` 을 실행해 레포를 고른다(레포 관리자 권한과 `gh auth login` 필요).
   Claude GitHub 앱, `CLAUDE_CODE_OAUTH_TOKEN` 시크릿(구독 토큰을 고른 경우. API 키면 `ANTHROPIC_API_KEY`),
   `.github/workflows/claude.yml` 이 준비된다.
2. 워크플로 파일은 브랜치로 push 되고 PR 작성 화면이 열린다. 그 PR 을 만들어 기본 브랜치에 머지해야 `@claude` 가
   동작한다. 봇도 그때부터 버튼을 붙인다(`/digest` 로 바로 확인할 수 있다).
3. 봇의 `GITHUB_TOKEN` 에 그 레포의 Issues 쓰기 권한을 더한다. 토큰의 주인은 그 레포에 쓰기 권한이 있는 사람 계정이어야
   한다. Action 은 쓰기 권한이 없는 사용자나 봇 계정이 올린 이슈에는 반응하지 않는다.

Action 의 기본 동작이라 이 봇이 바꾸지 못하는 것들:

- 기본 설정의 Claude 는 PR 을 직접 열지 않는다. 브랜치를 push 하고 이슈 댓글에 PR 작성 링크를 남긴다.
  그 링크로 PR 을 만들기 전에는 다이제스트의 "열린 PR"에 나오지 않는다.
- Bash 도구가 기본으로 꺼져 있어 테스트를 돌리지 못한다. 돌리게 하려면 워크플로의 `claude_args` 에
  `--allowedTools "Bash(npm:*)"` 처럼 그 레포의 명령을 허용한다.
- 이슈 기능이 꺼진 레포(포크는 기본으로 꺼져 있다)에는 이슈를 올리지 못한다.

## 끄기

그 레포의 기본 브랜치에서 `.github/workflows/claude.yml` 을 지운다. 다음 다이제스트부터 그 레포의 버튼이 붙지 않는다
(봇이 "준비됨"을 기억하는 한 시간 안의 `/digest` 에는 아직 나올 수 있다). 이미 올라간 다이제스트의 버튼은 남는다.
누르면 이슈는 올라가지만 받아 줄 워크플로가 없다.
